# 要素类和要素数据集

## 总结
要素类（Feature Class）是 GDB 中最小的矢量图层单元，要素数据集（Feature Dataset）是统一坐标系的逻辑容器，用于支撑拓扑、网络等高级空间关系功能。

---

## 知识点 1：要素类（Feature Class）

### 定义
存储同一几何类型地理对象的集合，对应 GIS 里一张矢量图层（等价于 shp 文件）。
- 几何类型只能单一：**点 / 线 / 面 / 注记 / 多面体**，不能混存
- 自带属性表，每条记录 = 1 个地理要素
- 可以独立存放在 GDB 根目录，也可以放进要素数据集内部

### 举例
- **点要素类**：水井、GPS 测点、路灯
- **线要素类**：道路中心线、河流、等高线
- **面要素类**：宗地、行政区、湖泊

---

## 知识点 2：要素数据集（Feature Dataset）

### 定义
GDB 内部的逻辑容器，专门收纳一批**共用同一空间参考（坐标系 + 容差）**的要素类。

- 创建数据集时必须指定唯一空间参考
- 内部所有要素类强制继承这套坐标系，不能各自设坐标
- **核心作用**：支撑高级空间关系功能（这些功能只能建在要素数据集里）
  - **拓扑 Topology**：宗地共边、边界无缝、不重叠规则
  - **网络数据集 / 几何网络**：交通路网、管线管网
  - Terrain 地形、宗地结构、公共设施网络、线性参考 LRS

### 通俗比喻
- Geodatabase = 一个文件柜
- **要素数据集 = 一个文件夹**（规定好统一坐标系）
- **要素类 = 文件夹里一张张矢量图纸**（每张只能是点/线/面一种）

---

## 知识点 3：核心区别对比

| 对比项 | 要素类 Feature Class | 要素数据集 Feature Dataset |
|--------|---------------------|---------------------------|
| 本质 | 矢量数据图层（真实数据表） | 逻辑分组容器（虚拟文件夹） |
| 坐标系 | 可单独设置 | 内部所有要素类共用一套 |
| 存在形式 | 可独立放在 GDB 根目录 | 只能存在 GDB 内部 |
| 几何限制 | 只能单一种几何 | 内部可混合点、线、面 |
| 高级功能 | 不能直接建拓扑、网络 | 唯一能承载拓扑、路网、地形 |
| 使用场景 | 单一独立图层（如全国省界） | 一组关联图层（水系：河线、湖面、水库点） |

### 存放的两种方式
1. **独立要素类**（GDB 根目录）：只有单独图层、不需要拓扑/网络时使用
2. **要素数据集内要素类**：多图层存在空间约束关系时使用

### 示例
新建 `hydrology` 水系数据集（CGCS2000），内部放入：
- `point_well`（水井点）
- `line_river`（河流线）
- `polygon_lake`（湖泊面）

再在数据集内创建拓扑，约束河流必须落在湖泊边界上。

---

## 简单总结
1. **要素类是数据本身**，是要加载出图的矢量图层
2. **要素数据集是收纳盒子**，只为统一坐标、实现拓扑/网络等高级 GIS 分析
3. 没有拓扑、管网需求时，完全可以不用要素数据集，直接在 GDB 根目录新建要素类
